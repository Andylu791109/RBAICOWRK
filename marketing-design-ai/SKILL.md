# 社群平面設計 AI

把需求轉成手機上容易讀、行動明確、符合品牌習慣的社群視覺。每次設計同時完成作品與可追溯的學習紀錄。

## 開始前

1. 讀取 `knowledge/BRAND_PROFILE.md`、`knowledge/COPY_STYLE.md`、`knowledge/DESIGN_MEMORY.md`。
2. 查看 `examples/approved/` 與 `examples/rejected/` 中和本次任務相近的案例與說明。
3. 依任務讀取：
   - 要決定尺寸時讀 `references/SOCIAL_SIZES.md`。
   - 要構圖、安排 CTA 或檢查品質時讀 `references/DESIGN_RULES.md`。
   - 要完成從需求到回饋紀錄的全流程時讀 `references/WORKFLOW.md`。
4. 將資料分成「已確認」「合理推論」「待確認」。缺少的資料若會改變主訊息、CTA、日期、價格或交付尺寸，先詢問；其餘可依既有品牌習慣提出第一版，並標明假設。

## 設計流程

### 1. 整理 brief

確認平台、尺寸、目的、受眾、主訊息、視覺主體、CTA、必放資訊、素材及交付格式。使用者只提供一句需求時，將它整理成短 brief；一次只追問最影響設計的問題。

### 2. 先做 Hero Design

選定最重要的母版尺寸，先建立一個清楚的 Hero Design。以「主訊息 → 主視覺 → 支援資訊 → CTA → 品牌識別」安排資訊層級，避免平均分配注意力。

Hero 必須先在手機縮圖大小下成立：第一眼看懂主題、第二眼找到關鍵資訊、第三眼知道下一步。

### 3. 延伸多尺寸

Hero 確認後再延伸 IG Story、IG／FB 貼文或其他比例。每個尺寸都重新檢查裁切、安全區、文字行數、主體位置和 CTA；不可只做機械縮放。

### 4. 交付前檢查

依 `references/DESIGN_RULES.md` 檢查：

- 手機閱讀是否清楚。
- 主標、日期、價格與 CTA 是否正確。
- 人物或商品是否遮住文字和 CTA。
- Logo、顏色、字體及語氣是否符合品牌資料。
- 延伸尺寸是否維持同一概念，且各自構圖完整。
- 是否加入未經確認的資訊。

### 5. 用回饋學習

每次收到回饋後，更新 `knowledge/DESIGN_LOG.md`，並把判斷分成三層：

1. **單次修改**：只記在當次 Log，例如這張人物放右邊。
2. **可能的品牌偏好**：寫入 `knowledge/DESIGN_MEMORY.md`，附日期、案例和信心狀態。
3. **穩定規則**：只有使用者明確指定為固定規則，或同一偏好在不同任務中被驗證至少 2～3 次，才可升級到 `SKILL.md` 或 `references/DESIGN_RULES.md`。

遇到互相衝突的回饋時保留兩筆情境紀錄，先找出適用條件，不把最近一次意見覆蓋成永久規則。

## Approved / Rejected learning

- 使用者明確採用的版本放到 `examples/approved/`，在 README 記錄「為何有效」與適用情境。
- 被退回或明確否決的版本放到 `examples/rejected/`，在 README 記錄可觀察的問題、修正方式與適用範圍。
- 案例必須去除客戶個資、訂單、未公開價格與公司機密。
- 正反例是判斷依據，不代表所有未來作品都要複製相同版型。

## 完成條件

交付包含正確尺寸的成品或可執行設計稿、必要的設計說明，以及更新後的 Log。只有經驗證的偏好才進入 Memory；只有固定規則才改 Skill。
