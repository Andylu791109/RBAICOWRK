# 今天的練習資料

沒有帶自己的資料，或一時想不到題目，就從下面挑一組跟你工作最像的，**整段複製貼進對話框**。

所有範例都是教學用的虛構資料，不是公司真實的客戶、訂單或規則。每人只選一組，不必全部做。A–C 是共用案例，D–I 補充部門入口。

---

## A　客服事件：把一串對話整理成回報

### 第一份資料

```
09/10 09:10　顧客表示收到一個杯子，訂單頁顯示兩個
09/10 09:20　客服請顧客提供開箱照片，目前尚未收到
09/10 09:35　倉庫回報揀貨紀錄為兩個，尚未核對包裹重量
09/10 09:50　顧客希望週五前收到缺少的商品
09/10 10:00　客服主管要求先整理目前資訊，再決定如何處理
```

**你可以先這樣問**：幫我整理這件客訴。

**看結果的時候注意**：它會不會寫出「倉庫漏寄」「已確認補寄」「週五前送達」。這三件事上面的紀錄裡**一件都沒有**。

**修正句**：把顧客反映、已知紀錄與待確認分開，不要把期待寫成補寄承諾。

**做出來應該長這樣**：顧客反映什麼／已經有的紀錄／還要確認什麼／顧客的期待（還不是我們的承諾）／要主管決定什麼。

### 換一份資料再試（有餘裕或課後延伸）

**這一輪是在延續同一工作，接著原對話貼。** 課後若要測試小抄重用，才另開新對話，並把小抄與新資料一起貼上。

```
09/11 14:00　主管決定補寄一個杯子
09/11 14:20　倉庫確認庫存足夠，今日出貨
09/11 14:30　物流尚未提供預計到貨日
09/11 15:00　顧客詢問什麼時候會到
```

**要看的是**：它會不會保留「已決定補寄」這個確定的事，同時**不亂承諾到貨日期**。

## B　叫貨差異：兩張表對不起來

### 第一份資料

規則：**款號和顏色都一樣才算同一筆**。差額＝應叫數量減已叫數量。
算出來是負的代表叫多了，請直接寫成「多叫 3」，不要寫成負 3。

```
應叫數量
款號  顏色  數量
A01   黑    10
A01   白    8
B02   藍    6

已叫數量
款號  顏色  數量
A01   黑    7
A01   白    8
B02   藍    9
```

**你可以先這樣問**：幫我看這兩張表哪裡不一樣。

**看結果的時候注意**：它會不會把 A01 的黑跟白合併成一筆算。那是最常見的錯。

**修正句**：款號與顏色一起配對，兩邊不匹配的列待確認，不要自行合併。

**做出來應該長這樣**：A01 黑少 3、B02 藍多 3。一致的那筆可以不用列。

### 換一份資料再試（有餘裕或課後延伸）

**這一輪是在延續同一工作，接著原對話貼。** 課後若要測試小抄重用，才另開新對話，並把小抄與新資料一起貼上。

已叫數量多一筆，應叫表裡完全沒有。**兩張表都重貼一次，比較保險**：

```
應叫數量
款號  顏色  數量
A01   黑    10
A01   白    8
B02   藍    6

已叫數量
款號  顏色  數量
A01   黑    7
A01   白    8
B02   藍    9
C03   紅    5
```

**要看的是**：C03 紅會不會被列成「待確認：應叫表沒有這個品項」。被安靜忽略、或自己算成多叫 5，都是錯的。

## C　活動內容：把一句話變成能用的文案

### 第一份資料

```
商品：隨行杯
容量：480ml
顏色：米白、深藍
售價：390 元
活動期間：9/15–9/20
```

**你可以先這樣問**：幫我做一個活動貼文。

**看結果的時候注意**：它會不會寫出保溫時數、折扣、材質。上面**一個字都沒提到這些**。

**AI 問發布情境時可回答**：給粉專新朋友看，希望他們知道這款杯子的商品與活動資訊。

**修正句**：只用我提供的商品資料，保溫、材質與折扣沒提供就不要寫。

**做出來應該長這樣**：一則可供人工確認的貼文草稿，而且它在動筆之前先問過你要發在哪、給誰看。商品資料一個字都沒被改動。

### 換一份資料再試（有餘裕或課後延伸）

**這一輪是在延續同一工作，接著原對話貼。** 課後若要測試小抄重用，才另開新對話，並把小抄與新資料一起貼上。

```
商品：隨行杯
容量：480ml
顏色：霧粉、炭灰
售價：420 元
活動期間：9/22–9/27
```

**要看的是**：新版本裡還有沒有殘留舊的顏色或價格。

## 卡住的時候

先按工作選一組：客服用 A、採購／出貨用 B、行銷用 C；業務 D、產品 E、執行長辦公室 F、SPA 館 G、人資 H、財務 I。主管可以選自己部門同一組，改成「要給主管判斷的五行摘要」。

- **不知道要問什麼** → 跟它說：「我說不上來哪裡怪，你問我。」
- **它問太多問題** → 跟它說：「先做五行給我看，我看了再說。」
- **它自己編東西** → 跟它說：「資料裡沒有的不要補，不確定的列成待確認。」
- **它連已經確定的事也標成待確認** → 跟它說：「這件事紀錄裡已經寫死了，照寫，不要標待確認。」
- **帳號被鎖住** → 舉手，跟同桌一起看一個畫面，講師有預先做好的稿子給你。

## 有餘裕或課後：留下下次能用的小抄

做出滿意的版本之後，跟它說這一句：

> 幫我整理成下次可以用的。

它會先產出可複製的 Markdown 小抄，把固定規則與每次要換的資料分開；你再確認待確認欄位。

**課堂必交：第一版、指出一個問題、具體修正、修改後版本與下一件工作。** MD 小抄是有餘裕或課後延伸，不取代成果卡。把小抄複製到純文字檔存為 .md，下次與新資料一起貼進新對話，確認沒有沿用舊日期或金額。

## D　業務：直播前，活動資訊有兩個版本

```text
用途：給直播同仁的五行活動口播草稿。
商品資料：隨行杯 480ml，售價390元。
企劃草稿：活動9/15開始，可能送杯刷。
9/12核定通知：活動9/16–9/20，贈品尚未核定。
業務需求：交代活動期間與價格，提醒哪些資訊不能先講。
```

起手句：幫我整理直播要講的活動資訊。
核對：日期應用9/16–9/20；不能把「可能送」變成確定贈送。
修正句：核定通知優先，贈品只放內部待確認，不放口播。

## E　產品：到貨和請款數量不同

```text
用途：整理給產品主管看的請款差異。
配對規則：品號與規格都一致才配對。
到貨：P01／480ml／8個；P02／600ml／5個。
請款：P01／480ml／10個；P02／600ml／5個。
補充：是否分批到貨尚未確認，單價未提供。
```

起手句：幫我找出要確認的請款項目。
核對：P01請款比到貨多2個；不能推定溢收金額或廠商請錯款。
修正句：列出數量差異即可，原因和金額先待確認。

## F　執行長辦公室：會議紀錄混著提案與決議

```text
用途：給與會主管確認決議與待辦。
會議紀錄：有人建議下週推出隨行杯活動，尚未拍板。
已決議：產品窗口於9/16補齊商品規格。
已決議：業務窗口於9/17回報通路需求。
未定：活動上線日、預算與負責統整的人。
```

起手句：幫我整理會後待辦。
核對：只列兩項已決議待辦；提案不可寫成下週確定上線。
修正句：決議與提案分開，未指定的負責人不要自行安排。

## G　SPA 館：表單摘要要先分清已確認與詢問

```text
用途：交班時查看9/16的預約及活動詢問。
預約表：代碼S01，9/16 14:00，已確認；S02，9/16 15:00，待回覆。
詢問表：S01詢問活動可否合併使用；S03詢問9/16是否有空位。
活動規則：尚未提供。
要求：分成已確認、待回覆、活動待確認，不新增預約。
```

起手句：幫我整理9/16交班重點。
核對：已確認只有S01一筆，S03詢問不等於預約；不可自行允許優惠合併。
修正句：把詢問和預約分開，不要把詢問計入預約總數。

## H　人資：只先整理到職準備這一段

```text
用途：人資確認到職前準備，使用虛構代碼，不含個資。
本次檢查項目：到職日、資料繳交、設備安排。
N01：9/21到職；資料已齊；設備尚未回報。
N02：到職日待確認；資料尚缺一項，項目未註明；設備已安排。
只整理狀態與缺件，不發通知、不評分、不推定負責人。
```

起手句：幫我看哪些到職準備還沒完成。
核對：N01只缺設備狀態；N02的到職日與缺件名稱待確認。
修正句：只列缺漏和下一個需要確認的問題，不要重做整套人資流程。

## I　財務：付款資料先做完整性檢查

```text
用途：付款整理文字樣本，尚未取得正式匯入格式。
練習欄位：單號、日期、金額、幣別。單號重複先標疑似重複，不自行刪除。
F01，9/15，1200，TWD。
F02，9/16，金額空白，TWD。
F01，9/15，1200，TWD。
F03，9/17，50，USD。
```

起手句：幫我把這些付款資料整理好。
核對：F01兩筆均保留並標記；F02缺金額；TWD與USD不能直接加總。
修正句：重複只標記，缺值不要補0，未取得正式規格前不要說能直接上傳。
