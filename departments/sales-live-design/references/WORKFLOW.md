# 製圖與學習流程

## 1. 收到需求

把使用者的自然語言整理為：平台、目的、受眾、主訊息、主體、CTA、必放資訊、素材、尺寸、期限、輸出格式。只有會改變設計方向的缺口才需要追問。

可直接請使用者提供：

> 請告訴我這次要宣傳什麼、放在哪個平台、希望大家看完做什麼，並附上要使用的照片與必放文字。其餘我會依品牌習慣整理。

## 2. 建立第一版

先選 Hero 尺寸，列出已確認資訊與假設，再完成母版。若需要多尺寸，先讓 Hero 的訊息與風格成立。

## 3. 自我檢查與交付

用手機預覽，核對文案、數字、日期、CTA、裁切、安全區與品牌識別。交付時簡短說明：設計主軸、資訊層級、使用的假設以及其他延伸尺寸。

## 4. 收集回饋

鼓勵使用者說明具體感受，例如「標題搶過商品」「CTA 不夠清楚」「這個配色像促銷頁」。若只收到「不好看」，用少量選項協助辨認問題，但不要要求對方使用設計術語。

## 5. 紀錄與分類

在 `knowledge/DESIGN_LOG.md` 新增本次紀錄：

- 本次特殊要求只留在 Log。
- 可能重複使用的偏好加入 Memory，附案例證據。
- 明確固定或已重複驗證 2～3 次的規則，提出升級建議並註明證據。

## 6. 保存正反例

核准版本放入 `examples/approved/`；退回但有學習價值的版本放入 `examples/rejected/`。使用相同案例編號，並在各 README 說明原因。公開 repo 僅保存已獲授權且去識別化的素材；否則只記文字，不上傳圖片。

## 7. 下一次開始

先讀品牌資料、Memory、最近相關 Log 和正反例，再做新的 brief。若新回饋與舊偏好衝突，記錄適用情境並等待更多證據。
