# 主管查看與維護方式

這套流程讓業務夥伴透過公開網址接受 AI 引導，主管則透過 GitHub 保留可查看的組織記憶。

## 主管查看位置

| 想查看的內容 | 位置 |
|---|---|
| 每次直播設計與修改紀錄 | `knowledge/DESIGN_LOG.md` |
| 正在形成的設計偏好 | `knowledge/DESIGN_MEMORY.md` |
| 最終採用案例 | `examples/approved/` |
| 未採用案例與錯誤原因 | `examples/rejected/` |
| 已確認品牌資料 | `knowledge/BRAND_PROFILE.md` |

## 每次回報的處理方式

1. 業務夥伴把 AI 產出的《直播設計回報》傳給主管或 repo 維護者。
2. 將內容整理進 `DESIGN_LOG.md`，保留日期、專案、修改與採用原因。
3. 有未來重複價值的偏好才加入 `DESIGN_MEMORY.md`。
4. 已獲授權且完成去識別化的作品，才放入 approved 或 rejected。
5. 同一偏好跨不同直播任務被驗證 2～3 次後，再決定是否升級為固定規則。

## 可見性限制

公開連結能讓沒有 GitHub 帳號的同仁讀取指引，但不能讓其 AI 對話自動寫回 GitHub。現階段以《直播設計回報》作為交接文件，主管確認後再保存；這也避免未確認的單次意見直接改動公司規則。

若未來要做到自動回寫，需要另外建立有身分驗證的表單或內部入口，再由該入口將回報送進 repo。上線前要先決定誰能提交、誰能核准，以及哪些圖片可以保存。
