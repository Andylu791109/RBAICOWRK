# 交付前自檢表

送出給主管之前，先自己走一遍。左邊六項是**跨部門通用**，整理自業務、財務、行銷、SPA、跨部門五位主管實際回答的驗收標準；右邊再依自己部門加做。

未通過的項目不要硬改成通過，改成「待確認」並寫清楚缺什麼，本身就是合格的交付。

## 通用六項

| # | 自檢項目 | 沒做到會發生什麼 |
|---|---|---|
| 1 | **每個數字與說法都回查得到來源**：寫出取自哪份資料、哪個欄位、哪段期間。 | 主管第一個問題就是「這數字哪來的」，答不出來整份退回。 |
| 2 | **推測與已確認分開標示**：確定的寫確定，沒證實的一律標「待查」，不寫成原因。 | 推測被當成公司結論用出去，事後很難收回。 |
| 3 | **缺漏明確列出**：缺的資料、衝突的來源、過期的版本，列成清單，不靜悄悄跳過。 | 主管以為完整，用到一半才發現少東西。 |
| 4 | **每項都有可執行的下一步**：誰做、做什麼、什麼時候前完成。 | 交出去只是一份報告，沒有人接得下去。 |
| 5 | **計算與加總自己先驗過**：來源總額、處理後總額、差異三個並列；差異不為零就標待核，不標可用。 | 加總錯是最容易被抓到、也最傷信任的錯。 |
| 6 | **不超出現實限制與合規**：現場資源、人力、預算、法規與對外宣稱，超出的部分標為待主管核定。 | 方案看起來漂亮但做不出來，或對外講出不能講的話。 |

## 各部門加做

| 部門 | 額外要自檢 |
|---|---|
| 業務 | 目標、客群、主題、商品與優惠彼此邏輯一致；直播流程與前置準備沒有重要缺漏；每項任務都有責任人、期限與進度狀態。 |
| 財務 | 缺件項目標示清楚且正確；每筆差異金額都附具體來源可查核；可能原因只列待查。 |
| 行銷 | 清楚指出成效變化與目標落差，能快速看出重點；每個問題判斷都附對應數據；官網與廣告營收未經釐清不得相加。 |
| 產品 | 內容清楚分成「已確認產品事實／AI 轉譯內容／待人工確認事項」；法規、功效宣稱與品牌銷售表達已標為需人工確認。 |
| SPA | 主題回應顧客需求且有吸引力；SOP 不超過現場床位與人力限制；效益與折扣財務合理且已控風險；對外宣稱符合合規。 |
| 跨部門平台業績 | 分類有判定依據；組合拆解可回查原訂單、原組合名稱、組數與換算式；分類後數量與金額加總正確。 |
| 人資與總務行政 | 主管驗收標準尚待確認，暫以通用六項為準，並在交付時請主管補充。 |

## 送出時附一句話

交付時一起寫上這三件事，主管才知道能不能直接用：

1. 這份是**草稿／待核／可用**（「可用」要註明是自己判斷還是主管已確認）。
2. 哪些地方**還沒有人工核對過**。
3. 需要主管決定的**待確認事項**有哪幾項。
