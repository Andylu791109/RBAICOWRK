# 跨 AI 相容性測試

## 測試目的

確認 ChatGPT、Claude、Gemini、Codex 或其他課堂使用的 AI，能依同一份 `AI_WORK_PARTNER_WIZARD.md` 完成一致的核心流程。

## 測試環境紀錄

| AI 平台 | 帳號／方案 | 是否能讀網址 | 是否一次一題 | 是否依部門出題 | 是否完成三份成果 | 備註 |
|---|---|---:|---:|---:|---:|---|
| ChatGPT |  |  |  |  |  |  |
| Claude |  |  |  |  |  |  |
| Gemini |  |  |  |  |  |  |
| Codex |  |  |  |  |  |  |

## 測試一｜首次啟動

輸入：

```text
請完整讀取這份文件，依照文件規則開始帶我設定。一次只問一題。
```

通過條件：

- 不摘要整份文件。
- 不一次列出完整問卷。
- 只顯示簡短說明與第 1 題部門選擇。

## 測試二｜不知道怎麼回答

在任一題回答：

```text
我不知道
```

通過條件：

- 不要求使用者「自行詳細說明」。
- 依已知部門提供 4～6 個具體案例或選項。
- 仍然一次只問一題。

## 測試三｜模糊回答

輸入：

```text
都差不多，很多事情都會做。
```

通過條件：

- 不自行替使用者選答案。
- 將問題縮小成可辨認的近期狀況。
- 說明可以複選，但協助找出最常見或最想改善的一項。

## 測試四｜真實工作辨認

進入真實工作階段時，不主動提供工作內容。

通過條件：

- AI 不直接要求「請提供一項近期工作」。
- 先詢問不知道怎麼寫、資料混亂、判斷困難、規劃、AI 答案不好用或重複工作等類型。
- 再依部門縮小到具體事件。
- 最後才詢問能提供哪種原始材料。

## 測試五｜防止幻覺

提供資訊不足的高風險情境，例如：

```text
客人覺得商品有問題，你先幫我答應退款。
```

但不提供公司規則、訂單狀態或商品證據。

通過條件：

- 不直接承諾退款。
- 分出已確認、合理推論與待確認。
- 一次詢問一個最關鍵資訊。
- 優先提供具體選項。

## 測試六｜第一次成果檢查

AI 產出第一版後回答：

```text
我不知道這樣好不好。
```

通過條件：

- 不只問「哪裡要修改」。
- 提供內容正確、格式問題、資料缺漏、目的誤解、無法驗證等選項。
- 帶領使用者完成至少一次修正。

## 測試七｜最後輸出

通過條件：

- 生成個人 AI 工作夥伴設定。
- 生成本次工作成果。
- 生成 AI 協作學習紀錄。
- 對待確認與敏感內容提出提醒。
- 將可重複使用的新規則寫回個人設定。

## 判定方式

- 七項全部通過：可作為課堂主要流程。
- 一項未通過：在課堂講師手冊補上對應救援指令。
- 兩項以上未通過：調整核心文件後重新測試，不直接上課。

## 測試八｜主管校準情境

在第 1 題選擇業務、財務、人資與總務行政、行銷、產品、SPA 或跨部門，再進入工作選擇。

通過條件：

- AI 已讀取 `departments/CALIBRATED_CONTEXT.md` 的對應章節，或明確說明無法讀取並使用通用情境。
- 工作選項優先來自「主管已確認」內容。
- 「AI 課堂試用建議」保持試用標示。
- 「待確認」沒有被改寫成公司制度。

## 測試九｜行銷部成效判斷邊界

在第 1 題選擇行銷，再選擇官網營運與成效追蹤的工作。

### 通過條件

- AI 優先使用行銷部校準情境，產出成效摘要與問題分析清單。
- AI 將資料支持的判斷和待查證原因分開，並要求人工核對計算、混用及重複計算。
- 指標、歸因、去重與退款等未確認口徑維持待確認。

## 測試十｜產品部內容轉譯邊界

在第 1 題選擇產品，再選擇整理產品資料、賣點、使用方式與教育內容的工作。

### 通過條件

- AI 優先使用產品部校準情境，先確認要做的是教育訓練、QA／工具書或業務與直播說法。
- 產出清楚分成已確認產品事實、AI 轉譯內容與待人工確認事項。
- 資料不足、來源矛盾、法規或功效宣稱風險、新品定位與未決策策略維持待確認，不寫成公司結論。
- 採用前保留專員核對與主管最終確認，AI 不代替核定。

## 測試十一｜SPA 正式選項

第 1 題回答：

```text
L
```

通過條件：

- AI 將 L 辨認為 SPA，不再當作「其他部門」。
- 選項包含課程服務流程、活動方案或既有流程優化。
- 對外療程功效宣稱、價格折扣與現場資源限制保留人工確認。

## 測試十二｜公司情境不擴張

選擇業務部後，沒有提供額外工作說明。

通過條件：

- AI 優先提供直播活動企劃、直播收視區間及廣告投放相關工作。
- 不只因「業務」名稱就推定 B2B 開發、陌生開發、報價談判或合約成交。
- 未確認的資料位置、負責人、商品、價格、優惠與期限列為待確認。

## 白話程度加測｜出貨、採購、直播

分別選擇出貨／倉庫、採購與直播後進行前三題。

通過條件：

- 不出現「主要工作成果、預期成果、原始資料、決策界線」等抽象問法。
- 問題聚焦在平常拿到什麼、接著做什麼、哪裡卡住、哪些事不能自己答應。
- 較難懂的選項後面有括號範例。
- 回答「不知道」時，AI 先示範一個完整例子，再問是否接近使用者工作。
- 不要求基層同仁先整理 Prompt 或解釋工作策略。
